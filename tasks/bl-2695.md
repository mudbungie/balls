`message::run_git` (src/message.rs:148) spawns git with piped stdin, then:

    .write_all(stdin.as_bytes())?;
    let out = child.wait_with_output()?;
    if !out.status.success() { /* the bl-dede error: "git {args}: {stderr}" */ }

The `?` on `write_all` is the hole. When git fails FAST — an unknown
subcommand, a usage error — it exits and closes the read end before the write
lands, and the write returns EPIPE. That error propagates instead of the status
check ever running, so the caller gets

    Broken pipe (os error 32)

instead of

    git not-a-git-subcommand: 'not-a-git-subcommand' is not a git command...

which is exactly the failure bl-dede fixed: "the exit status is checked at the
spawn, where the failure actually is." EPIPE reinstates the useless voice one
layer up — the operator sees a pipe error naming no git command and no reason.

It is a RACE, so it is intermittent by construction: the 7-byte payload fits
the pipe buffer, so the write only fails if git has ALREADY exited. Observed as
a flaky close-gate abort under load (two concurrent tarpaulin runs, 2026-08-11):

    ---- message::tests::a_git_that_exits_non_zero_is_an_error_not_an_empty_parse
    panicked at src/message_tests.rs:113: Broken pipe (os error 32)

The test that guards bl-dede is the thing that catches it, which is the system
working — but it fails a whole close gate for a defect in the code under test,
not in the test.

Fix: a BrokenPipe from the stdin write is never the interesting error — the
child's exit status is. Swallow that one errno and let `wait_with_output` plus
the status check speak, which is already the only path that can say what went
wrong. Every other write error still propagates.

Needs a test that pins the race deterministically rather than hoping for load:
a payload past the pipe buffer (64 KiB) against a git that exits without
draining stdin makes EPIPE certain every run instead of one time in a hundred.
