MODE 1 of bl-cdec, and worse than reported.

`Project::deliver` (src/delivery_repo_acts.rs) does: reintegrate(fold `integration` into work/<id>) -> gate(10-13 min pre-commit hook) -> ensure_no_resurrection -> commit-tree(tree=work^{tree}, parent=rev-parse integration) -> commit_swap CAS.

The fold reads `integration` at T0. The parent and the CAS old-value are read at T2, AFTER the gate. So the CAS validates 'integration has not moved since a moment ago' when the invariant that matters is 'integration has not moved since the tree I gated was computed'. Two consequences:

1. FALSE ABORT (reported): a sibling close lands mid-gate, its paths are not in this branch's authored set, so ensure_no_resurrection sees them as excess and aborts NAMING them as a resurrection. Observed 3x by one agent. Wrong voice, and a whole gate run wasted.

2. SILENT REVERT (not reported, worse): if the mover's changed paths are a SUBSET of the paths this branch authored (two agents editing one shared file — architecture.md, a shared module), ensure_no_resurrection finds no excess, the CAS succeeds against the post-move tip, and the squash tree — computed from the pre-move fold — REVERTS the sibling's landed change. No error, no reflog clue beyond the squash itself.

Fix: pin the base. Read base = rev-parse(integration) BEFORE reintegrate; use it as commit-tree's -p, as commit_swap's old-value, and as ensure_no_resurrection's comparison point. Then a mid-gate move is one clean rejection at the ref flip in bl-a3bb's existing voice ('integration moved under the delivery ... re-run bl close'), the resurrection invariant goes back to detecting only real resurrections, and the silent-revert window closes structurally. No new state: one variable, moved earlier.
