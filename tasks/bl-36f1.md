During the bl-cdec close (2026-07-26, heavy concurrent load: a sibling repo's agent fleet plus balls agents), the pre-commit gate failed 3 consecutive times on tests/import_roundtrip.rs — '2 passed; 1 failed' — once surfacing via cargo test and once via tarpaulin ('Test failed during run'). The same binary passed standalone immediately after each failure, passed a manual full-suite parallel run mid-window, and passed two later gates (oakum's bl-ffbf close and the final bl-cdec close) — so it is load- or interleaving-sensitive, not deterministic. The failing test's name was never captured (cargo test --quiet + truncated capture; lesson: capture the failures block). The three tests (from bl-e5c0): plain_import_round_trips_a_ball_byte_for_byte, a_colliding_stream_is_refused_wholesale_before_any_write, minted_ids_match_the_scheme_and_never_duplicate. Known patterns to check first: cross-binary env races (env::set/remove_var siblings — the HOME/PATH precedent, two fix patterns exist in-repo), the git-SHA same-second coincidence pattern, and whether bl-1fc4's new minting code changed these tests' assumptions. Reproduce under load (e.g. run the full suite in a loop while a parallel build saturates cores) and instrument before assuming.
