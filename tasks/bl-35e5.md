From CONVERGED docs/design/bl-0161-cross-repo-work.md (Q3, ratified 2026-07-04). Today enrolling a satellite into a center is multi-step with a half-enrolled failure window (binding set but config not adopted, or the reverse — the state the cross-tracking trial kept hitting); the maintainer's verbatim complaint that started this: 'getting everything configured right is so painful that even I find it tedious.'

DELIVERABLES. (1) `bl prime --center URL` — prime-only, durable by definition, sugar for the composition that already exists: bl conf set task-remote URL (per-clone binding, bl-d081) + prime --install URL (consent-gated adoption of the center's committed config/, single hop, sealed commit = the undo) + ordinary prime (clone/sync, converge). One command from any satellite checkout, zero origin surgery, no global-XDG trap, no half-enrolled window. Re-running is prime-idempotent (binding write converges, install converges, sync ffs). A filesystem path is a legitimate center (two repos on one box share through a local bare repo — same code path as a hosted one). (2) Drop --center as an ephemeral --remote alias on non-prime verbs (--remote stays everywhere): one flag meaning durable-here/ephemeral-there is worse; pre-1.0, cheap now. The rule reads: --remote shapes one op; --center enrolls a checkout. NOTE: this alias-drop was settled by consequence, not addressed directly by the maintainer — it is veto-able; if vetoed, keep the alias and document the asymmetry.

TRUST FRAMING (do not widen install's gate): the one-shot names its source explicitly in argv, the copy is the same visible sealed commit, bin/ never travels (§6) — the trust act is identical to today's two-step, merely spelled once.
