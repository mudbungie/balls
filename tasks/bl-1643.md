Source: yog bl-673a. speculate_run::build runs the gate and takes status.success() as the whole answer, writing Verdict { pass } unconditionally — the gate has exactly two answers to give it. But a gate can die for reasons that are not a judgement of the tree: five sightings on yog (2026-08-14/15) of the GitHub runner signaling cargo-tarpaulin mid-suite (every prior test green; the macOS leg of the same tree green). Because a stored FAIL is permanent — speculate_run reads it and stops the chain there on every later pass without rebuilding, keyed by tree — each infrastructure death became a permanently false-negative tree.

yog's side is done (yog bl-673a, delivered): its coverage step retries once on the signaled class and exits 75 (EX_TEMPFAIL) meaning 'no verdict'; its speculate.yml records nothing on 75; its speculate-gate treats an empty verdicts artifact as a rebuild, not an answer. The residual is here: two consecutive infrastructure deaths still store a FAIL, because speculate_run::build cannot be told 'record nothing'.

Ask: reserve one gate exit code (75, BSD EX_TEMPFAIL, is the natural one) meaning no verdict — do not write a verdict file, do not stop the chain on it, treat the candidate as unbuilt. Every other non-zero stays a FAIL verdict as today. Verify against the tree; this body drifts.
