Two reproduced modes on the lernie repo, 2026-07-26: (1) a work branch rooted before a force-push rewrite of main counts ~120 upstream commits as branch-own; the squash message concatenates their messages and exceeds Linux MAX_ARG_STRLEN (128KB) — observed 142-143KB, 'bl-delivery: Argument list too long (os error 7)'. (2) A work branch containing a hand-resolved merge commit (from an earlier aborted close) reproducibly blows the same limit even after the pre-commit gate passes — four consecutive failures; a zero-diff close on a clean branch succeeded. Workaround both times: reset the work branch to main and re-apply the work as a single clean commit, then close. Suggested fix: build the squash message from the branch-own commit set bounded by the merge base (or truncate/summarize past a size cap), and pass the message via file/stdin (git commit-tree -F -) rather than argv.
