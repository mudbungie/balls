bl-5d8b added README "Bootstrapping a repo for agents", whose first piece is an AGENTS.md in the project tree doing DISCOVERY — the hop that tells a fresh agent balls exists at all, which balls cannot write for you (§11, core never opens the project repo). The balls repo itself has no AGENTS.md. An agent landing here learns about `bl` only if its operator already knew.

That is worse than an ordinary missing file, because this repo is the reference implementation of the advice: the absence reads as the advice not being meant.

Deliverable: a short AGENTS.md at the root. It must obey the rule the README states one paragraph later — POINTERS, NOT COPIES. It names `bl --skill` as the entry, `docs/architecture.md` as the frozen authority, and the README for install and the gate; it restates none of them, and it is not a second home for the spec.

Deliberately NOT in scope: a `config/PRIME.md` for this repo. That is the landing half of the same bootstrap and a separate decision — the two files have separate jobs, and conflating them here would be the exact drift the README warns about.
