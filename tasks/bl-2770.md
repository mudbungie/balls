src/speculate.rs:

    const GATE_FILES: &[&str] = &[
        "scripts/pre-commit",
        "scripts/check-line-lengths.sh",
        "scripts/check-coverage.sh",
        "Makefile",
    ];

gate_fingerprint() does fs::read(root.join(rel))? over that list — a missing file is an io::Error, so in any repo not shaped exactly like balls, `bl-speculate check` and `record` exit 1 forever. Fail-open makes this INVISIBLE: the stock gate runs, nothing complains, and the whole speculative merge queue is silently inert.

Observed adopting the queue for yog (yog bl-1a5b, 2026-08-12): yog's gate lived in .githooks/pre-commit and had no scripts/check-line-lengths.sh or scripts/check-coverage.sh; yog had to refactor its gate into balls' exact file layout (including a delegator script that exists chiefly to be fingerprinted) before the cache would compute at all.

The smell against the house principles: policy (which files ARE the gate) is baked into the core instead of living in the capability/consumer. The severability test fails — adopting the queue in a new repo edits that repo's gate layout rather than declaring config.

Possible shapes (not prejudging): derive the list from the repo (hash the resolved pre-commit hook and everything reachable?), a per-repo manifest, or keep the fixed list but document it loudly as the plugin's contract and make check/record distinguish 'gate files absent' from other errors so the inertness is at least diagnosable.
