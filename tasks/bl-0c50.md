skill/show.md:13 currently reads:

> **Agents should always parse `--json`, never the tty view.**

Revert that guidance. Agents read a ball the way anyone does — the default human render IS the read surface. `--json` is the formal, completionist path: the lossless bedrock mirror you reach for when round-tripping (`bl import`), diffing exact stored fields, or integrating from outside. It is not the everyday read.

The guidance costs real information, because everything derived is human-only by design (the §3 bedrock-vs-render split): the journal (`-m` notes, §9), the derived claim-age line, the machine-local `worktree` line, the `delivers <id>` line. Architecture §9 states the intent plainly — "so a handoff reads the prior agent's notes in place" — but an agent obeying show.md never sees a journal entry in its life. Every `-m` note an agent writes is written for a reader the docs told not to look. That is why notes never landed.

Scope: `skill/show.md`. Sweep the sibling skill docs (`list.md` especially) for the same instruction and fix it there too.

Do NOT touch architecture.md's "a machine integrator reads bedrock `--json`" passages (§3/§9, around lines 294 and 3206). External integrators reading bedrock is correct and stays — the conflation being fixed is "agent" with "external machine integrator".

Principle: the derived render is the interface; bedrock is the export.
