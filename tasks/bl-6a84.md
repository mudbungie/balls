`balls::speculate::gate_fingerprint` hashes a FIXED list — `Makefile`,
`scripts/pre-commit`, `scripts/check-line-lengths.sh`, `scripts/check-coverage.sh`
(confirmed by `strings` on the installed 0.x binary). The doc premise in yog's
`scripts/pre-commit` is right — "change any of them and every stored verdict
silently stops matching, which is exactly the invalidation a gate upgrade must
cause" — but it only holds for gates that happen to live in those four files.

yog (bl-fd5a) adds `scripts/leak-scan.sh`, a real gate step invoked from
`make lint`. Editing it changes what the gate ENFORCES while every stored
verdict keeps matching: a tree that passed under the old scanner skips the new
one. The failure is silent and in the safety direction that matters least
(a weakened rule passes), which is the worst kind.

Fix: the fingerprint file list belongs to the repo, not the binary. Read it
from the landing (or a repo manifest), defaulting to today's four so nothing
moves for existing users. Single source of truth: the repo already knows what
its gate is made of.
