# Shift the --skill surface from one monolith to a two-tier, per-command model

## Why
Today `bl skill` prints one 367-line monolith (`SKILL.md`); every agent loads
the whole manual to learn any one verb. An agent that just needs claim/close
should not have to read all of prime/install/conf. Isolate the depth per
command so the reader pays only for what they use — while keeping ENOUGH at the
top that nobody footguns themselves (e.g. `claim` without `--as`), yet not so
much at the top that they never open the subordinate doc.

## The surface (after)
Top-level:
- `bl --skill`  -> the operational guide (canonical, NEW).
- `bl skill`    -> same guide + a note it is on a DEPRECATION PATH (kept for now).
- `bl help` / `--help` / `-h` -> terse command directory, still generated from
  Verb::ALL (unchanged; the one surviving generated surface, drift-proof).

Per-command (all three spellings -> ONE prose doc):
- `bl <cmd> --skill` = `bl <cmd> --help` = `bl help <cmd>` -> `skill/<cmd>.md`.
  Per-command `--help` FOLDS INTO `--skill` (maintainer decision 2026-07-04):
  one per-command doc, no separate terse tier. Cost accepted: loses the
  generated per-command flag table (flags become prose), keeps the exhaustive
  'every verb has a doc' guarantee via the skill match.

## Decomposition boundary (the judgment call)
Top-level guide keeps ONLY cross-cutting invariants + the map:
- what balls is; the default flow (claim->work->close->done, one agent finishes
  its own task); architecture ('all simple git + worktrees in XDG folders' -
  where config/ tasks/ work/<id> live);
- the FOOTGUN SET: run `bl prime --as ID` first; always pass `--as`; all edits go
  in the claimed work/<id> worktree, never main; status is derived not stored;
  close is pre-commit-gated; stdout carries one product (use --json to parse);
- the command map, each line -> 'bl <cmd> --skill for full usage';
- the `bl skill` deprecation note.

Per-command docs get that command's depth. Cross-cutting MODELS live in their
authoring command with a one-line top-level pointer:
- blocker/dependency model -> `bl create --skill` (referenced from update);
- plugin model -> `bl conf --skill` (schedule) + `bl install --skill` (binding).

## Files
- SKILL.md -> shrunk to the top-level guide.
- skill/<verb>.md x12 -> per-command docs (usage + flags + examples + semantics).
- NEW src/skill.rs -> top() + command(verb): exhaustive match over Verb,
  include_str! per arm (a new verb can't ship without its doc).
- DELETE src/help_command.rs and help::command(); per-command help now = the
  skill doc.
- src/dispatch.rs -> route --skill top-level and per-command; `skill` prints
  guide+banner; per-command --help/-h/`help <cmd>` route to skill::command.
- src/help.rs -> keeps only directory(); its footer + directory point at --skill.

## Definition of done
100% coverage, all files < 300 lines (md exempt), full suite green, and every
`bl <verb> --skill` / `--help` prints that verb's doc.
