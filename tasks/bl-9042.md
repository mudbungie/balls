The surviving open item from umbrella bl-cdec, now focused. Since bl-8b89 a mid-gate main advance is a clean, correctly-voiced CAS rejection — but the retry re-runs the entire pre-commit gate (10-13 min on lernie under load), and under sustained close traffic an unlucky close can starve indefinitely. bl-cdec's original wants: (a) close re-folds main and re-runs the hook in a bounded loop, or (b) a delivery ticket/lease so concurrent closes serialize instead of wasting whole gate runs. docs/design/bl-cdec-atomicity.md leaves this open as 'option 1: nothing beyond G1' vs 'the delivery lease'. Tension to resolve by dialogue, not first draft: any lease/loop is new mechanism and new state in the one path that is currently a single clean CAS; the seal-level equivalent was explicitly rejected (bl-fa89: converge-on-retry is the documented rule). But the delivery gate is orders of magnitude dearer than the seal, so the retry-is-one-command argument is weaker here. Evidence to gather before deciding: observed starvation frequency now that aborts are clean (the 3x-per-agent count predates bl-8b89's pin). PROMOTED: architect-owner's call.
