Raised by the bl-baa0 fix (main 68789a8e). prime's debris report now computes, per stale work/<id> branch, both facts that would make deletion provably lossless: the ball is closed (no task file — absence is the record) and the branch's content is contained in the integration tip (merge-tree). Today it still only ADVISES git branch -D; the branches accumulate forever and are re-reported on every prime.

Proposal: let the Settled/closed+contained arm delete the branch itself, ending the recurring noise. The uncontained arm stays advisory (read the diff first), as does every open-ball arm.

Why this is a design ball and not a fix: it reverses the deliberate stance in docs/design/bl-18bf-prime-convergence.md that prime never deletes what may hold work — prime's one deletion license would widen. The claim to attack: closed + contained is exactly the condition that rule exists to protect, so deletion there is not an exception to the rule but its satisfaction. Attack surface: false containment verdicts (merge-tree semantics vs squash-delivered content), a race where the ball is closed but the branch gains a commit after the containment check, and whether silent deletion loses forensic value (the branch is the only record of HOW the work happened, even when its tree landed).

PROMOTED: needs the architect-owner's call before implementation. Deliverable if approved: amendment to the bl-18bf design record + the Settled-arm deletion + tests pinning both the deletion and the surviving advisory arms.
