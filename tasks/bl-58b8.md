Raised by the bl-baa0 fix (main 68789a8e). prime's debris report now computes, per stale work/<id> branch, both facts that would make deletion provably lossless: the ball is closed (no task file — absence is the record) and the branch's content is contained in the integration tip (merge-tree). Today it still only ADVISES git branch -D; the branches accumulate forever and are re-reported on every prime.

Proposal: let the Settled/closed+contained arm delete the branch itself, ending the recurring noise. The uncontained arm stays advisory (read the diff first), as does every open-ball arm.

Why this is a design ball and not a fix: it reverses the deliberate stance in docs/design/bl-18bf-prime-convergence.md that prime never deletes what may hold work — prime's one deletion license would widen. The claim to attack: closed + contained is exactly the condition that rule exists to protect, so deletion there is not an exception to the rule but its satisfaction. Attack surface: false containment verdicts (merge-tree semantics vs squash-delivered content), a race where the ball is closed but the branch gains a commit after the containment check, and whether silent deletion loses forensic value (the branch is the only record of HOW the work happened, even when its tree landed).

PROMOTED: needs the architect-owner's call before implementation. Deliverable if approved: amendment to the bl-18bf design record + the Settled-arm deletion + tests pinning both the deletion and the surviving advisory arms.

Evidence from bl-4d38, which attacks this ball's delete CONDITION directly.

bl-58b8 proposes deleting on 'closed + contained'. The containment half is unreliable, and I have both directions measured on this repo's own debris.

contained(branch, integration) is a TREE-IDENTITY test against a MOVING reference, so its verdict DECAYS. Of the five pre-bl-ce3b relic branches standing here on 2026-08-12, two read 'NOT contained in main' while nothing whatsoever was stranded:

  work/bl-3f97 (bl-chore child, parent bl-0c50 — landed)
  work/bl-8513 (bl-chore child, parent bl-236c — landed)

  $ git diff --stat main...work/bl-3f97
   SKILL.md      | 14 +++++++++-----
   skill/list.md |  4 +++-
   skill/show.md | 23 +++++++++++++++++++++--
   3 files changed, 33 insertions(+), 8 deletions(-)

Those 33 lines are the branch's OLDER COPY of doc files main has since been edited past by later balls — not stranded work. The delivery landed inside the parent's squash; main then moved. So this ball's own listed attack surface ('false containment verdicts (merge-tree semantics vs squash-delivered content)') is CONFIRMED, and it is not an edge: it fires on every nested child once the integration tip advances past the delivered files.

Consequence for the proposal as written: the advisory arm this ball preserves ('the uncontained arm stays advisory — read the diff first') is precisely the arm that is WRONG, and the deletion this ball would license would skip exactly the branches that are safest to delete. The condition is inverted in practice.

The stronger condition is CLOSED ALONE, and it needs no containment test at all. Ordering proves it: close.pre squashes, THEN the seal removes tasks/<id>.md, THEN close.post deletes the branch. No task file therefore implies the seal ran, which implies the squash ran — the content was delivered, wherever §11 sent it. That is not a new argument; it is verbatim the one bl-ce3b already used to license close.post's own delete, src/delivery.rs:194-201:

  'Ordering is the whole safety argument for the close arm. The blanket deferral bought
   insurance against deleting the ONLY copy of an undelivered diff — real, and EXPIRED by
   the time this hook runs: close.pre squashed and the seal landed before any post fires,
   and an abort BEFORE the squash never reaches here. prime's prune stays as the backstop
   for a crash between the seal and this line.'

prune's closed arm is that same state. Re-deriving delivery there by content archaeology against a reference §11 made per-ball is the mismatch bl-4d38 filed; deleting the archaeology dissolves it, and drops contained() to a single caller (standing).

Also note the POPULATION this ball is designed for has collapsed. bl-58b8 says 'the branches accumulate forever and are re-reported on every prime' — true when filed (2026-07-27), false since bl-ce3b landed 2026-08-07T04:03:07Z. All five relics were closed BEFORE that commit (the last three by under two minutes); zero have leaked in the five days since, under heavy traffic. They are now swept (git branch -D, 2026-08-12). The recurring noise this ball exists to end is already ended at the source; what remains is a crash-only backstop, which argues for LESS mechanism here, not a widened license with a per-branch merge-tree behind it.

The forensic-value attack listed above also weakens on inspection: four of the five relics carried NO commit of their own (chore no-op closes leave the child branch pointing at the parent's tip), so there was nothing to preserve.
