Born from bl-0bd8 (tests/invocation_scope.rs pins that the substrate is keyed on the LITERAL cwd). Capability, not policy: every verb accepts a global -C <path> (git/make convention) that becomes invocation_path verbatim — the store addressed is exactly the one keyed by <path>. No walking, no git detection, no fork: -C is the explicit signal, so any future auto-resolution policy can layer on top and this stands alone if that never happens (severability).

Serves: scripts/agents driving a project store from elsewhere; running bl from inside a work/<id> worktree (today the deep mirrored path can ENAMETOOLONG on encode — -C <project-root> sidesteps it); deliberately founding or addressing a nested sibling-subdirectory store (a sane use case — never prohibit it).

Implementation: the crate seam already exists — run() takes invocation_path and src/main.rs:20 passes env::current_dir(). Parse -C before verb dispatch (global flag, every verb), canonicalize, refuse a nonexistent path in balls voice, pass through. Keep the crate interface taking the path as a parameter (callers override the same way the CLI does).

Docs: SKILL.md invariants mention the global flag; bl help directory line; skill/<verb>.md pages reference it where --remote is already listed as a global-ish flag. Tests: e2e — from an unrelated cwd, bl -C <project> list/create/claim address the project store; -C a-path-with-no-store behaves exactly like cwd there (prime founds, reads are silent-empty); -C nonexistent refuses.
