Found while landing bl-dede (main a246906a), 2026-07-31. src/delivery_repo_gate_tests.rs::install_hook writes a pre-commit hook into the fixture repo's .git/hooks, but when the operator has a global core.hooksPath set (this box: ~/userconf/githooks-global, a 'chain' symlink that is always present and executable), git resolves the GLOBAL path — Project::gate never sees the installed hook. Consequence: a_non_executable_hook_is_ignored_gits_rule asserts nothing about the hook it installs, and delivery_repo.rs:193 (the non-executable-hook skip arm) is covered only incidentally. Not failing today (pristine main measures 100%), but the fixture is one environment change away from a mystery coverage failure — the exact class that already bit once: bl-61e0 had to pin core.hooksPath in delivery_repo_tests.rs::project() because that leak DID uncover delivery_repo.rs:193 (99.98% on pristine main, no close could pass). Fix: same one-liner, git config core.hooksPath <root>/.git/hooks inside install_hook (or lift the pinning into the shared fixture both files use, if one exists — prefer the single shared home). Test-only change; the ball is about hermeticity, not behavior.
