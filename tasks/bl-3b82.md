Found while building bl-upstream (bl-5273). Repro: git init --bare hub.git; mkdir d; bl -C d prime --center $PWD/hub.git --as x → 'bl: git worktree add --detach .../changes/install-src FETCH_HEAD: fatal: invalid reference: FETCH_HEAD' and the store is never materialized (later ops die on a missing tasks/). --remote works, and 'conf set task-remote' after it gives the durable bind, so bl-upstream founds that way. Expected per skill/prime.md ('A filesystem path is a legitimate <hub>' and bl-45fd's 'a stock hub carries no balls/config'): --center on a config-less hub should bind + prime and skip the adopt as a no-op, the same §13 'upstream, if any' rule install.pre already applies. The fix is the adopt's guard: no FETCH_HEAD (nothing fetched) ⇒ nothing to adopt, not a fatal.
