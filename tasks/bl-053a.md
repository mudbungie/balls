The XDG plugins.toml [hooks] overlay (bl-8540) composes the schedule, but
dispatch still resolves every name through the landing's config/plugins/bin/
registry — so a machine-globally wired plugin aborts every op in every landing
(and every future prime) until each is hand-bound with bl install --bin. That
makes the machine layer unusable for its one job: wiring a box-wide plugin
(e.g. a leak gate before bl-tracker) once.

Design: locality of the naming layer decides the resolution surface.
- Landing-committed names keep the registry discipline (they travel; an adopted
  config must not silently run a same-named PATH binary).
- Names the MACHINE's own xdg plugins.toml contributes resolve like
  clock_provider (bl-cfe3): registry bin/<name> first if bound, else beside bl
  (edge.exe_dir), then $PATH (edge.path_dirs). The same "this machine" lookup,
  minus the symlink, because the xdg layer never travels either.

Implementation sketch:
- Hooks::effective records the xdg layer's contributed names (a machine set).
- Hooks::refs takes the machine lookup (closure or dirs) and falls back for
  machine-origin names when registry.resolve_bin misses.
- conf dump: a machine-resolved name is bound (no unbound row); layer column
  already says landing+xdg.
- Seed prune and install binding read the committed landing schedule alone —
  unchanged (the dispatch-only rule holds).
- Amend docs/architecture.md §6 with the machine-layer resolution rule.
