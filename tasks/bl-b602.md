release-plz pushes a new timestamped `release-plz-*` branch every time it refreshes the release PR, and leaves the old one behind. balls had 3 stale branches from already-merged release PRs; those have been deleted by hand and "Automatically delete head branches" is now enabled on the repo, but that setting only fires on MERGE — it does nothing for release PRs that get closed as superseded, or for branches orphaned when PR creation fails.

Add a `prune-release-branches` job at the end of `.github/workflows/release-plz.yml`. It runs right after the release-PR job, so the branch backing the current release PR is already open, and "has no open PR" is an exact test for "superseded or orphaned".
