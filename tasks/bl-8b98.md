Add a single-point clock override in the balls repo so an external caller (the bl-workhours wrapper) can pin the frontmatter clock, keeping published task timestamps consistent with the git commit dates it also sets via GIT_*_DATE.

THE CHANGE (one function, src/mutate.rs):
now() -- documented in-source as 'The SOLE site that reads the wall clock and reduces it to §3 unix seconds' -- reads env BALLS_CLOCK first; if set and it parses to i64, return it; else fall through to SystemTime as today.

    fn now() -> i64 {
        if let Ok(s) = std::env::var("BALLS_CLOCK") {
            if let Ok(n) = s.trim().parse::<i64>() { return n; }  // fail-open on garbage
        }
        SystemTime::now()...   // unchanged
    }

CONSTRAINTS:
- Fail-open: unset OR unparseable -> real clock. Behavior byte-identical when unset.
- Touch ONLY mutate::now() (frontmatter created/updated, published on balls/tasks). Do NOT touch log.rs::wall() -- the local op log is diagnostic, never published, and must stay honest (design §4).
- Mechanism, not policy (severability, §0): core learns it can be TOLD the time; it learns nothing about windows/work-hours/personas. Those live entirely in the wrapper.
- Bonus/independent justification: this doubles as a deterministic-clock test seam for core (today only git dates are pinnable via test_support.rs; frontmatter timestamps are non-deterministic in tests).

TESTS: unset -> real; valid int -> that value in created/updated; garbage -> real (fail-open). 100% coverage gate.

DOCS: one-line note in architecture §3 (unix-seconds field) and/or §8 (seal) that now() honors BALLS_CLOCK as a test/override seam. bl-chore docs child applies.

Design: ~/dev/bl-workhours/docs/design.md §4 (Seam B).
