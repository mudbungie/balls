The old .github/workflows/release-plz.yml ran the release-plz action with its
default command on every push to main, so it did release-pr AND release in one
ungated step — a version could publish off a commit CI had not gone green on,
and no binaries were ever attached to the GitHub Release.

Replace it with the three-job layout matching brazen:

* release-pr on push to main (queues the release PR),
* release gated on the CI workflow concluding success (`workflow_run`),
* release-binaries in the same run: builds bl/bl-delivery/bl-chore for
  x86_64-unknown-linux-gnu and uploads the archive to the Release.

release-plz.toml gains the same explanatory header as the other repos; its
patch-by-default + [minor]/[major] opt-in policy is unchanged in substance.
