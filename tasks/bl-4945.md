Found while landing bl-3129 (main 86d7f9e1). push's E5 contention message advertises 'run bl sync, then re-run the command'. That recovery works only because a rejected push un-seals the loser, leaving the store un-diverged so sync's ff-only converges. But a crash between seal and push — the bl-547f half-close shape — leaves a sealed-but-UNPUBLISHED commit: sync then refuses non-ff forever (correctly, and since bl-3129 its voice at least NAMES the state: 'keeps refusing while this store carries commits the remote never took'), and E5's advertised recovery dead-ends. Nothing converges the state automatically; the operator remedy today is a manual push of the store branch. Related: bl-547f (the half-close family) and bl-1266 (aborted-claim commits already published — the mirror image: here local has what remote lacks, there remote has what local rolled back). Whatever design bl-1266 converges on should say which side owns reconciliation; this ball is the reminder that E5's sentence needs to match the answer.
