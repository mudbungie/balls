## The rule

Every task delivers to a **target ref**, derived, never stored: if the task close-gates its live parent (`--parent X` + `{this, on: close}` edge on X), the target is `work/<X>`; otherwise it is the integration branch (main). The root case is the degenerate case — main is just what a parentless task delivers to. The full target is a tuple **(root, ref)**: federation pins the root (distinct root_commits ARE the fleet, root-SET admit), this design pins the ref. Claim forks the target ref; close folds the target in, runs the repo pre-commit hook, and plumbing-merges back to the target. The hook at the root close gates what actually lands on main.

## Why (bl-54fe)

A verification gate wants "claimable once the parent's work exists, before the parent delivers" — unexpressible when close IS delivery-to-main, so agents wire vacuous gates (`--blocks close` alone) or deadlocks (`+ --needs parent`), recurring (lernie 2026-07-11, 15 mis-wired tasks). Under nesting the documented spelling `--parent X --blocks close` becomes CORRECT AS WRITTEN: the gate's claim forks X's live branch, verifies against the work it gates, merges back; no repair edge, no cycle. The footgun was never the graph — claim only knew how to fork main.

## Already in place

- Delivery is ref-addressed plumbing: `delivery_repo.rs` recomputes from `(path, branch)`, squash = commit-tree + update-ref, never disturbs a checked-out tree (bl-ee85/§11/§14).
- Worktree is a machine-local cache, path computed never stored (§7) — the ref is the SSOT, so no filesystem↔branch 1:1 is needed.
- Close delivers committed `work/<id>` WIP regardless of claim state (bl-65e0) — an epic closes without a standing claimant session.

## Settled by dialogue (2026-07-11)

- **Lazy ref mint, not worktree materialization, not refusal**: first child claim mints `work/<epic>` as a bare ref at main's head — nothing to orphan. Children merge in by plumbing; the epic never needs a worktree. The branch is the holder, so no agent carries the epic's lifecycle.
- **Offramp is the existing signal, no knob**: close-gate edge = nesting declaration; bare `--parent` (containment-only) stays flat-to-main. Nesting requires BOTH parent pointer and close-gate on that parent; `--blocks ID:close` on a non-parent stays pure enforcement.
- **`--subtask-of` flips** from claim-gate to close-gate (the one behavior change); old claim-gated children carry no close-gate so existing epics keep flat delivery untouched — self-migrating.
- **Distribution is a plugin**: core touches only local refs; a claim.pre fetch / close.post push (-u on mint) plugin makes a distributed epic work; push races fail at close.post = the intended half-close direction (bl-c3c0). Federated wrong-repo pickup is the same offramp: an upstream on the target ref.
- **bl-chore endpoint**: impl becomes a sibling like test/doc; the epic is a pure integration container; every child delivers into the epic branch; one main-delivery, one hook run on what lands.

## Open

- Hook at child close: uniform (fold target, hook, merge — elegant, keeps unit coverage riding impl) vs root-only. Leaning uniform.
- Child closes become provisional: closed children's work lives on the epic branch until the root closes; abandoning a claimed epic destroys closed children's delivered work. Close honestly means "delivered to target" — the doc must own this edge.
- Ready checkmark/gate children are dispatchable to strangers mid-flight — bl-6c84 (dispatch signaling) residue, not solved here.
- bl-54fe keeps its independent cheap fixes (write-time cycle refusal, create-skill note) — cross-referenced, not gated.
